# Implementation contract

API base is `/api`. Cookies are HTTP-only. Mutations require same-origin or configured APP_ORIGIN. JSON errors `{code,message}`. Member, membership and class records use UUIDs. Catalogue IDs preserve source slugs. DTO shapes are defined in `packages/shared/src/index.ts`. Dates YYYY-MM-DD, Riyadh timezone, inclusive ends; catalogue durations explicitly fixed days (90/180/365). Prices are SAR numbers validated to at most two decimal places. The product does not settle payments.

Public: GET `/public/site` -> PublicSite. GET `/public/schedule?month=YYYY-MM` -> `{classes:ClassSession[]}`.

Admin: POST `/admin/login` `{username,password}`; GET `/admin/me` -> `{username}`; POST `/admin/logout` -> `{ok:true}`; POST `/admin/credentials` `{currentPassword,username?,newPassword?}`. GET `/admin/stats` -> DashboardStats. GET `/admin/members?q=&status=&page=` -> `{members:Member[],total,page}`. POST `/admin/members` MemberInput -> Member. PATCH `/admin/members/:id` partial MemberInput (nationalId optional), expectedVersion for membership edit. POST `/admin/members/:id/renew` `{planId,sports,expectedVersion,idempotencyKey}` -> Member. POST `/admin/members/:id/status` `{suspended,expectedVersion}` -> Member. DELETE `/admin/members/:id` -> soft archive. GET `/admin/members/export` -> CSV. GET `/admin/audit?memberId=` -> `{events:[{id,action,createdAt,actor,details}]}`.

Catalogue: GET `/admin/site` -> PublicSite with hidden/draft content. PUT `/admin/settings` ClubSettings. POST `/admin/plans` Plan sans id; PUT `/admin/plans/:id`; DELETE archives. Same routes for offers/coaches. PUT `/admin/content` `{blocks,expectedRevision}` saves draft; POST `/admin/content/publish` `{expectedRevision}` publishes; GET `/admin/content/history`; POST `/admin/content/restore/:revision` `{expectedRevision}`. POST `/admin/media` multipart file -> `{url}`.

Schedule: GET `/admin/classes?month=` -> `{classes}`. POST `/admin/classes` ClassSession sans id. PUT `/admin/classes/:id`; DELETE cancels. POST `/admin/classes/copy` `{from,to,preview,idempotencyKey}` -> `{classes,created,skipped,conflicts}`. No automatic yearly timetable. Staff must confirm and add the actual current schedule.

Communications: GET `/admin/messages` -> `{messages:MessageDelivery[],configured:{authentication,utility,marketing}}`. POST `/admin/announcements` `{title,body,target,memberId?,sendWhatsapp}` (marketing only for opted-in recipients), returns `{id,recipients}`. GET Meta verification `/whatsapp/webhook`; POST raw signed payload same path.

Member: POST `/member/login` `{nationalId,phone,authConsent:true,locale}` sends an SMS code and returns `{challengeId,maskedPhone}` after provider acceptance. Missing SMS configuration returns `SMS_UNAVAILABLE`; delivery failure returns `SMS_DELIVERY_FAILED`. POST `/member/verify` `{challengeId,code}` establishes session without changing saved preferences and returns `{ok:true}`. GET `/member/me` -> MemberDashboard. POST `/member/logout` -> `{ok:true}`. PUT `/member/preferences` `{updates,marketing,locale}` -> `{ok:true}`. POST `/member/announcements/read` `{ids}`. MessageDelivery includes `channel` (`sms`, `whatsapp` or development-only `local`); `accepted` means provider acceptance, not confirmed handset delivery.

No public/member fixture fallback for private data. Public content and schedule requests show retryable failures when the backend is unavailable. Production delivery mutations fail if their provider is unavailable. Explicit loopback-only development preview returns `developmentCode` on the login response, records `local` channel with `preview` status, and sends no SMS. This field is absent from real SMS login responses. Preview challenges cannot be verified outside the preview gate. Login challenges are bound to member phone and identity version. Tests focus on retry/transaction/authorization behavior.
